# 第三阶段规范：写操作（发送文字消息 + 自动回复）

> 基于 2026-09-10 clarify 共识小结制定。
> 关联文档：PRD.md、ROADMAP.md、SKILL.md

---

## 一、问题是什么

### 现状
- wechat-control 目前只有只读能力（查询/监控/语音转文字/AI总结），不能发送消息
- 用户需要发消息时，必须切换到微信手动操作，打断工作流
- 某些场景（如客服、群管理）有自动回复需求，但微信官方不提供

### 痛点
1. **手动发消息效率低**：需要切换应用、搜索联系人、输入、发送，步骤多
2. **无法批量/定时发送**：不能预设消息定时发送
3. **自动回复缺失**：客服场景、临时离开时无法自动回复
4. **风控顾虑**：第三方微信自动化工具（itchat/wechaty）封号风险高，用户不敢用

### 目标
- 实现安全的文字消息发送（手动确认模式）
- 探索自动回复的可行性（关键词/特定人触发，AI生成+安全过滤）
- 全程不注入、不重签、不调用私有 API，风控风险极低

---

## 二、方案是什么

### 选定方向
**UI 自动化操作微信官方界面**，通过 AppleScript + cliclick 模拟用户操作，不注入微信进程、不修改微信二进制、不调用私有 API。

### 为什么选这个方向
| 备选方案 | 优点 | 缺点 | 为什么不选 |
|---------|------|------|-----------|
| **UI 自动化（选定）** | 不注入不重签，风控风险低；操作可见可撤回 | 依赖界面布局，版本更新可能失效 | 风控安全第一，可接受维护成本 |
| 协议模拟（itchat/wechaty） | 功能强大，可后台运行 | 封号风险极高，微信官方打击 | 风控风险不可接受 |
| 注入/Hook（Frida） | 可调用内部 API，功能强 | 需要重签微信，触发风控 | 之前测试已触发强制下线+违规提示 |
| AppleScript 直接发消息 | 简单 | 微信 AppleScript 支持有限，不可靠 | 功能不足 |

### 技术实现
- **激活微信**：AppleScript `tell application "WeChat" to activate`
- **搜索联系人/群**：模拟 Cmd+F → 输入关键词 → 回车
- **输入消息**：cliclick 输入文字，或 AppleScript keystroke
- **发送**：模拟回车
- **自动回复监控**：复用 wx-cli 的 `new-messages` 轮询，AI 生成回复后走发送流程

## 三、User Stories

### 手动发消息

| ID | User Story | 验收标准 |
|----|-----------|---------|
| US-1 | 作为用户，我想对指定联系人/群发文字消息，以便不用切换到微信手动操作 | 用户说"给XX发消息：内容"，AI 展示"接收人：XX，内容：XXX"，用户说"发送"后执行，发送成功 |
| US-2 | 作为用户，我想在发送前确认接收人和内容，以免发错对象或内容 | AI 必须展示接收人+内容，用户必须明确说"发送"才执行；说"好""对""嗯"不发送 |
| US-3 | 作为用户，我想发送后知道可以撤回，以便发错了能及时补救 | 发送后立即提示"已发送，可在2分钟内撤回" |
| US-4 | 作为用户，我想修改起草的消息，以便内容更准确 | 用户说"改一下：新内容"，AI 更新内容并重新展示，等待确认 |
| US-5 | 作为用户，我想取消发送，以便不想发了可以中止 | 用户说"算了""取消""不发了"，AI 不执行发送 |

### 自动回复（探索性质）

| ID | User Story | 验收标准 |
|----|-----------|---------|
| US-6 | 作为用户，我想配置关键词触发自动回复，以便常见问题能自动应答 | 用户配置关键词（如"在吗""价格"），收到含关键词的消息时自动回复 |
| US-7 | 作为用户，我想配置特定人/群触发自动回复，以便只对特定对象自动回复 | 用户配置特定联系人/群，只对这些对象自动回复 |
| US-8 | 作为用户，我想 AI 根据消息内容自动生成回复，以便回复更自然 | AI 分析收到的消息，生成相关回复内容 |
| US-9 | 作为用户，我想自动回复有安全过滤，以免发不合适的内容 | 命中10类黑名单的内容不发送，记录日志并通知用户 |
| US-10 | 作为用户，我想自动回复有频率限制，以免刷屏触发风控 | 每分钟≤3条，每小时≤20条，同一对象5分钟≤2条，超限暂停 |
| US-11 | 作为用户，我想每次自动回复都收到通知，以便知道发生了什么 | 每次自动回复后通知用户：时间/触发人/原始消息摘要/回复内容摘要 |
| US-12 | 作为用户，我想自动回复有日志可查，以便事后回顾 | 所有自动回复记录日志（时间/触发人/原始消息/回复内容/是否成功） |
| US-13 | 作为用户，我想随时暂停/恢复自动回复，以便需要时手动控制 | 用户说"暂停自动回复"停止，说"继续自动回复"恢复 |
| US-14 | 作为用户，我想夜间不自动回复，以免打扰和风控 | 23:00-08:00 自动暂停，只记录日志不回复 |

## 四、已定的实现决策

### 4.1 手动发消息流程

```
用户："给XX发消息：内容"
  ↓
AI 解析：接收人=XX，内容=内容
  ↓
AI 验证：XX 是否存在于联系人/群列表
  ↓ 不存在
AI 反问："没找到XX，是指以下哪个？" + 候选列表
  ↓ 存在
AI 展示："接收人：XX，内容：内容，确认发送请说'发送'"
  ↓
用户回复：
  - "发送" → 执行发送流程
  - "改一下：新内容" → 更新内容，重新展示
  - "算了/取消" → 中止，不发送
  - 其他 → 不发送，等待明确指令
```

### 4.2 发送执行流程（UI 自动化）

```
1. 激活微信（AppleScript）
2. Cmd+F 打开搜索（cliclick/AppleScript）
3. 输入接收人名称（cliclick type）
4. 等待搜索结果（sleep 1-2秒）
5. 回车选择第一个结果
6. 等待聊天窗口打开（sleep 1-2秒）
7. 输入消息内容（cliclick type）
8. 回车发送
9. 等待发送完成（sleep 1秒）
10. 提示"已发送，可在2分钟内撤回"
```

### 4.3 自动回复流程

```
1. 后台轮询新消息（复用 wx-cli new-messages，每5分钟）
2. 检查触发条件：
   - 是否匹配配置的关键词？
   - 发送者是否在配置的特定人/群列表？
   - 是否在夜间（23:00-08:00）？→ 只记录不回复
   - 是否达到频率上限？→ 暂停，通知用户
3. 触发后，AI 生成回复内容
4. 安全过滤：检查是否命中10类黑名单
   - 命中 → 不发送，记录日志，通知用户"自动回复被拦截"
   - 未命中 → 继续
5. 执行发送流程（同手动发消息的 UI 自动化）
6. 记录日志（时间/触发人/原始消息/回复内容/是否成功）
7. 通知用户（摘要：时间/触发人/原始消息摘要/回复内容摘要）
```

### 4.4 安全过滤黑名单（10类）

1. 💰 金钱相关：转账、付款、红包、价格、金额、支付宝、微信支付、银行卡
2. 🔑 隐私敏感：密码、验证码、身份证、手机号、地址、个人信息
3. 📝 承诺保证："我保证""一定""肯定""没问题""包在我身上"
4. 🚫 敏感内容：政治、色情、暴力、赌博、毒品
5. 😠 辱骂攻击：脏话、骂人、歧视、威胁
6. 🏢 公司机密：内部数据、未公开信息、商业秘密
7. ⚕️ 专业建议：医疗诊断、法律意见、投资建议
8. 🎭 身份冒充："我是本人""是我""你连我声音都听不出来了"
9. 🤖 暴露AI："我是AI""自动回复""机器人"
10. ❓ 反问质疑："你是谁""你怎么知道"

### 4.5 频率限制

| 维度 | 限制 |
|------|------|
| 全局每分钟 | ≤3条 |
| 全局每小时 | ≤20条 |
| 同一个人/群 | 5分钟内≤2条 |
| 夜间 | 23:00-08:00 自动暂停 |

### 4.6 配置存储

- 配置文件：`~/.wx-cli/auto_reply_config.json`
- 日志文件：`~/.wx-cli/auto_reply_log.jsonl`（每行一条记录）
- 状态文件：`~/.wx-cli/auto_reply_state.json`（频率计数、暂停状态等）

## 六、不做什么（Out of scope）

### 本阶段不做
- ❌ 发送图片/文件/@消息（后续阶段再做）
- ❌ 自动回复的图形配置界面（先用 JSON 配置文件 + 自然语言配置）
- ❌ 多账号自动回复切换
- ❌ 朋友圈/公众号自动回复
- ❌ 群管理操作（拉人/踢人/改公告/群公告）
- ❌ 定时发送消息
- ❌ 批量发送/营销群发
- ❌ 消息撤回操作（只提示用户可在微信里手动撤回）
- ❌ 已发送消息的编辑/删除

### 永远不做（安全底线）
- ❌ 不注入微信进程
- ❌ 不重签微信
- ❌ 不调用微信私有 API
- ❌ 不修改微信数据库
- ❌ 不在大号上测试自动回复
- ❌ 不做绕过微信风控的操作

## 七、风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| 微信版本更新导致 UI 布局变化，自动化失效 | 中 | 中 | 锁定微信版本，关闭自动更新；失效后更新坐标/元素选择器 |
| 自动回复触发风控 | 高 | 低 | 严格频率限制+安全过滤；只在小号测试；出现异常立即停止 |
| 搜索结果不准确，发错对象 | 高 | 中 | 发送前展示接收人+内容，用户确认；搜索后验证聊天窗口标题 |
| cliclick 输入中文失败 | 中 | 中 | 备用方案：AppleScript keystroke，或剪贴板粘贴 |
| 微信窗口被遮挡，操作失败 | 中 | 中 | 操作前激活微信并前置；失败后重试，最多3次 |
| 自动回复内容不合适 | 中 | 中 | 10类黑名单过滤；用户可随时暂停；日志可查可撤回 |
