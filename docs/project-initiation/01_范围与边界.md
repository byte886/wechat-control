# 01 · 范围与边界 · wechat-control

> 补立项日期：2026-09-16 ｜ 本文档划定"做什么 / 不做什么 / 靠什么 / 怕什么"。
> 与 `docs/PRD.md` 附录 D 的 spec 互补：本文管边界，spec 管行为验收。

## 1. 做什么（In Scope）

三阶段能力，均已落地实现，本次立项只做治理整顿不改能力范围。

### 阶段一 · 只读查询（零风控）

基于 `jackwener/wx-cli` 解密微信本地 SQLCipher 4 数据库，AI 以自然语言查询：

- 会话列表与未读计数（`wx sessions` / `wx unread`）
- 聊天历史读取（`wx history`）
- 全库消息搜索（`wx search`）
- 联系人信息（昵称/备注/微信号/头像）
- 群成员列表
- 消息统计（数量、类型分布）
- 朋友圈读取
- 公众号消息读取
- 附件解密（图片/文件/语音 SILK V3 → 文本，经 `tools/silk-v3-decoder` + FunASR SenseVoiceSmall 本地转写）

只读路径只碰本地数据库文件，不碰微信进程、不联网、不操作微信界面。

### 阶段二 · 主动监控与每日总结

- `scripts/realtime-monitor.py`：新消息实时监听，daemon 自愈，33 种消息类型识别，重要性三级判定（高/中/低）。
- `scripts/wx-monitor.py`：群监控 + 每日消息摘要 + 推荐群 + 飞书同步。
- `scripts/voice-monitor.py` / `voice-transcribe.py`：语音实时/批量转写，本地运行不上传。
- 多渠道推送：控制台、日志、飞书（Webhook 规划中）。

### 阶段三 · 受控写操作（仅限小号 alt）

- `scripts/wx-send.py` + `scripts/wechat-ui/`：通过 AppleScript / cliclick 操作微信界面发送文字消息。
- 关键词自动回复（仅小号测试）。
- 风控硬闸：频率限制（每分钟 ≤3 / 每小时 ≤20 / 同对象 5 分钟 ≤2）、夜间静默（23:00–08:00）、黑名单（10 类敏感内容不发）、发送前 OCR 校验聊天对象。
- 多账号切换：`scripts/wx-account.sh` 在单官方 App 内切换主号/小号指向，配套 `third-party/wx-cli`（本人 fork 的多账号改造版，git 子模块）。

### 横切能力

- `mcp-server/`：FastMCP 服务（STDIO/SSE），把监控与查询能力以 MCP 工具形式暴露给上层 Agent。
- 双机同步：`.8`（本机）与 `.9`（对端）两台 Mac 共用同一公开仓，先子模块后父仓提交，对端 `git pull --ff-only`。

## 2. 不做什么（Out of Scope，红线）

以下能力**明确不做**，写入即拒绝：

| 不做 | 原因 |
|---|---|
| 加好友 / 删好友 | 高风控行为，超出只读工具定位 |
| 发朋友圈 / 点赞朋友圈 | 写操作且非私聊场景，风控面大 |
| 公众号发布 / 公众号自动回复以外的公众号写操作 | 同上 |
| 微信多开（同时跑多个微信实例） | 技术不可行且高风控，已用"单 App 内切换账号"替代 |
| 重签微信（`codesign --force --deep --sign -`） | 历史上曾触发强制下线 + 违规提示，红线 |
| Frida / lldb 持续注入 hook 微信进程 | 同上，红线 |
| 主号（main）执行任何写操作 | 主号只读，写操作仅限小号 alt |
| 消息正文 / 真实 wxid / 真实昵称入公开仓 | 公开仓零隐私纪律 |
| 绕过微信版本锁定（升级微信到 4.1.10+ 继续用） | wx-cli 硬性限制，不主动升级 |
| 云端转写语音（上传音频到外部 ASR） | 本地 FunASR 已是决策，不上传 |

## 3. 依赖与假设

### 外部依赖

| 依赖 | 版本/形态 | 说明 |
|---|---|---|
| 微信客户端 | ~4.1.8（锁定） | 4.1.10+ 密钥内存格式变更，wx-cli 扫不到 |
| wx-cli | 官方 npm 版 `@jackwener/wx-cli` 0.3.0+（单账号只读）；多账号须用本仓 `third-party/wx-cli` fork 源码编译 | 上游 Rust 实现密钥提取与 SQLCipher 解密 |
| macOS SIP | 已关闭 | 密钥提取 `sudo wx init` 需要；Windows 对应管理员权限 |
| Node.js | ≥ 18 | wx-cli 运行时 |
| Python | 3.9+ | 监控/转写/写操作脚本；FunASR + torch（体积大，按需装） |
| SQLCipher | 4.x | `brew install sqlcipher` |
| AppleScript / cliclick | 系统自带 / brew | 阶段三 UI 自动化发送 |
| FunASR SenseVoiceSmall | 本地模型 | 语音转文字，不上云 |
| `tools/silk-v3-decoder` | 第三方子目录 | SILK V3 → PCM |

### 关键假设（立项成立的前提）

1. **微信不会强制升级到 4.1.10+**——通过关闭自动更新 + 不主动升级维持。
2. **SIP 保持关闭**——重启后不重新 `csrutil enable`。
3. **同一账号、同版本、不重装微信则密钥长期有效**——不需要重复扫描内存。
4. **公开仓不会因技术披露被微信官方下架**——个人学习用途，README 已带免责声明。
5. **双机环境稳定**——两台 Mac 均为 macOS，路径用 `~` 自适应。
6. **小号（alt）风控容忍度足够**——写操作只在 alt 上跑，main 永不动。

## 4. 风险登记（轻量版，每周自查更新）

| 风险 | 概率(1-5) | 影响(1-5) | 应对 | 状态 |
|---|---|---|---|---|
| 微信被迫升级到 4.1.10+，`wx init` 失效 | 3 | 5 | 关自动更新；上游 wx-cli 跟进前不升级；备好时间点快照 | 监控中 |
| 写操作触发微信风控（小号也被限） | 2 | 4 | 严守频率/夜间静默/黑名单；一旦收到违规提示立即停写并复盘 | 监控中 |
| 密钥/账号信息泄漏到公开仓 | 2 | 5 | 三归宿纪律 + `git grep` 扫描 + 提交前 checklist | 监控中 |
| 公开仓历史中残留早期未脱敏内容 | 3 | 4 | 治理整顿期历史扫描；必要时走 filter-repo 清理 | 待排查 |
| 双机同步走了非 ff 路径导致仓乱 | 2 | 3 | 对端强制 `--ff-only`；先子后父提交纪律 | 监控中 |
| FunASR/torch 体积大、装失败 | 2 | 2 | 语音转写设为可选依赖，不用时不装 | 已缓解 |
| 上游 wx-cli 不再维护或 break | 2 | 4 | 多账号能力已 fork 到 `third-party/wx-cli`，可自维护 | 监控中 |
| SIP 被某次系统升级/恢复模式操作重新打开 | 1 | 4 | 重启后 `csrutil status` 自查 | 监控中 |
| daemon（realtime-monitor）泄漏内存或僵死 | 3 | 2 | daemon 自愈 + launchd/cron 守护 + 每周自查日志 | 监控中 |

## 5. 范围变更纪律

- 任何新增能力先回写本节 In/Out of Scope，再进 `docs/PRD.md` 附录 D。
- Out of Scope 表中的项若要解禁，必须走 ADR（见 `05_治理卡.md`），不能口头改。
- 风险登记每周日晚自查时更新概率/影响分。
