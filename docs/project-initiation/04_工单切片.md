## T-01 · 文档冗余清理

- **类型**：refactor / docs
- **目标（做成哪件"可见可验收"的事）**：把 `docs/` 下 8 篇设计文档与 `SKILL.md`、`README.md` 之间的重复章节去重，形成"一处权威、其余指针"的文档地图。
- **涉及层**：文档层（不改代码）
- **描述**：当前 `docs/PRD.md / FEATURES.md / ROADMAP.md / phase2-monitor-spec.md / phase3-write-spec.md / wechat-ai-agent-spec.md / monitoring-plan.md / database-schema.md` 与 `SKILL.md` 存在章节重叠（如安装步骤、风控红线、消息类型表）。以 `SKILL.md` 为运行面权威，`docs/` 退化为"为什么这么设计"的背景；README 只做门面。
- **验收标准**：
  - [ ] `docs/` 每篇文档开头有一行"本文档与 SKILL.md 的关系"指针。
  - [ ] 同一条技术结论（如锁版本 4.1.8、频率阈值）在全仓最多一处权威定义，其余用指针引用。
  - [ ] `SKILL.md §0` 明确写出"AI 运行时不加载 docs/"。
  - [ ] 文档地图（DOCUMENTATION_MAP）在 `docs/project-initiation/` 或 README 中可查。
- **依赖**：无
- **不属于本单**：不改任何脚本代码；不删 docs/ 下任何文档（只去重、加指针）。
- **预估工作量**：3 人时

## T-02 · 代码质量修复

- **类型**：refactor / bugfix
- **目标**：`scripts/` 下全部 Python 脚本通过 `py_compile`，无裸 `except:`，入口脚本有 `--help`，关键路径有日志。
- **涉及层**：代码层（Python / Shell）
- **描述**：治理历史上为快速落地写的脚本，统一异常处理与日志口径。不改业务行为。
- **验收标准**：
  - [ ] `python3 -m py_compile scripts/*.py` 退出码 0。
  - [ ] 全仓 grep `except:`（裸捕获）零命中。
  - [ ] 每个 `.py` 脚本 `--help` 打印用法。
  - [ ] 写操作相关脚本（`wx-send.py`）的拒绝事件必落日志。
- **依赖**：无
- **不属于本单**：不重写业务逻辑；不改频率阈值；不引入新框架。
- **预估工作量**：4 人时

## T-03 · 隐私加固

- **类型**：security / hygiene
- **目标**：公开仓当前树 `git grep` 零真实个人标识；历史残留有处置结论。
- **涉及层**：仓库层（含 git 历史）
- **描述**：按三归宿纪律扫描当前树与历史。当前树命中即修；历史命中且无法脱敏的走 filter-repo 清理或转 `.enc`。
- **验收标准**：
  - [ ] `git grep -iE 'wxid_|1[3-9][0-9]{9}'` 当前树零命中。
  - [ ] `git grep` 扫真实昵称/真实文件名占位符（按本机实际值替换后扫描）零命中。
  - [ ] 无 `Msg_<MD5>` 会话分表清单、无库文件大小/记录条数入仓。
  - [ ] 历史扫描结论落盘：哪些 commit 有残留、走了哪条处置路径（filter-repo / `.enc` / 删除）。
- **依赖**：无
- **不属于本单**：不清理本地 `~/.wx-cli/`（那是本机数据，不在仓内）。
- **预估工作量**：4 人时

## T-04 · 可移植性修复

- **类型**：refactor
- **目标**：全仓无硬编码本机用户名/路径，双机 `~` 路径一致。
- **涉及层**：代码 + 文档
- **描述**：历史上调试时可能写死了 `/Users/<用户名>` 或 `.8` 机器特有路径。统一改 `~` 或相对路径。
- **验收标准**：
  - [ ] 全仓 grep `/Users/<用户名>`（及本机另一台机的用户名）零命中。
  - [ ] 脚本中读微信数据目录用 `~` 或环境变量，不写死。
  - [ ] 在 `.9` 机上 checkout 同 commit，脚本路径引用不报错。
- **依赖**：无
- **不属于本单**：不改 `third-party/wx-cli` 子模块内部（那是上游 fork 的事）。
- **预估工作量**：2 人时

## T-05 · 冒烟测试体系

- **类型**：feature（测试基建）
- **目标**：`scripts/smoke.sh` 一条命令跑完 10 类只读 + 写操作 dry-run，退出码 0 即健康。
- **涉及层**：测试层（新建冒烟脚本）+ 现有脚本（不改行为，只加 dry-run 钩子）
- **描述**：这是治理整顿的"最高接缝"。AI/维护者以后只测这一条。
- **验收标准**：
  - [ ] `bash scripts/smoke.sh` 干净环境下退出码 0。
  - [ ] 覆盖 10 类只读：sessions / history / search / contacts / group-members / unread / stats / moments / official-account / attachment。
  - [ ] 写操作走 dry-run：账号闸（main 拒绝）、频率闸（连发越限拒绝）、夜间闸（模拟时间拒绝）、对象校验（OCR 不匹配拒绝）各有一条用例。
  - [ ] 任一子项失败时打印失败项名，退出码非 0。
  - [ ] 冒烟不真发送消息、不真改库。
- **依赖**：T-01（文档口径一致）、T-02（脚本可编译）、T-03（隐私不扫出问题）、T-04（路径可移植）
- **不属于本单**：不测 FunASR 精度；不做 CI（个人本地冒烟即可）。
- **预估工作量**：6 人时

## T-06 · 双机同步验证

- **类型**：QA / infra
- **目标**：`.8` 与 `.9` 同 commit 下冒烟结果一致，同步流程零冲突。
- **涉及层**：git 层 + 双机
- **描述**：验证"先子模块后父仓提交、对端 ff-only"流程真实可用。
- **验收标准**：
  - [ ] 两机 `git rev-parse HEAD` 相同、`git submodule status` 一致。
  - [ ] 两机 `bash scripts/smoke.sh` 退出码相同。
  - [ ] 对端 `git pull --ff-only` 无冲突、无 merge commit。
  - [ ] 同步 SOP 写入 `references/`（新增或并入 new-account-sop）。
- **依赖**：T-05
- **不属于本单**：不引入 CI/CD；不做自动双机推送。
- **预估工作量**：2 人时

## T-07 · MCP server 完善

- **类型**：feature
- **目标**：`mcp-server/server.py` STDIO 启动成功，至少暴露 3 个只读工具，README 与实现一致。
- **涉及层**：MCP 层（server.py + README）
- **描述**：当前 MCP server 已有雏形，本次把工具集收敛到最小可用集，并让 README 不骗人。
- **验收标准**：
  - [ ] `python mcp-server/server.py`（STDIO 模式）启动无报错。
  - [ ] `list_tools` 返回 ≥ 3 个只读工具（sessions / search / unread）。
  - [ ] 调用 sessions 返回非空会话列表。
  - [ ] MCP server 不暴露任何写操作工具（写操作走 CLI，不走 MCP，避免误触）。
  - [ ] `mcp-server/README.md` 与实际工具集一致。
- **依赖**：无（与主线并行）
- **不属于本单**：不做 SSE 线上部署；不把写操作工具暴露到 MCP。
- **预估工作量**：3 人时

> ✅ **完成回写（2026-09-17）**：MCP server 已落地并接入豆包桌面端自定义 STDIO 连接器（服务名 `wechat-monitor`）。实际工具集从原设想的通用 `sessions/search/unread` **收敛为监控向 5 个工具**：`get_new_messages` / `get_monitor_status` / `mark_messages_as_read` / `update_config` / `get_message_history`（只读 + 已读标记 + 监控配置，**不含任何微信发消息写操作**，满足本单"写操作不走 MCP"的实质要求）。STDIO 启动无报错（launchd 精简 PATH 问题由 `_resolve_wx_bin()` 回退探测修复，见 ROADMAP MCP-2）；`mcp-server/README.md` 工具清单与实现逐一对齐。唯一可靠重启方式＝豆包连接器开关关→开。
