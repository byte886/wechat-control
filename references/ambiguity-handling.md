# 歧义处理流程（wechat-control 参考）

> 当用户提到的群名/人名/公众号名有多个匹配结果时，必须先列出候选让用户确认，禁止猜测。

## 触发条件

满足以下任一条件时，触发歧义确认：
1. 用户提到的名称在 `wx sessions` 中匹配到 **2 个及以上**会话
2. 用户提到的名称在 `wx contacts` 中匹配到 **2 个及以上**联系人
3. 用户提到的名称同时匹配到群聊和私聊（类型不同）
4. 用户提到的名称模糊（如"那个群""上次聊的人"），无法确定具体对象

## 处理流程

### 第一步：搜索匹配
- 优先用 `wx sessions` 搜索（因为 sessions 包含最近有交互的群/人/公众号，且带最后消息摘要）
- 如果 sessions 里没有，再用 `wx contacts` 搜索全量联系人
- 搜索方式：不支持模糊搜索命令时，先获取完整列表再在结果中匹配关键词

### 第二步：列出候选
按以下格式列出候选，让用户选择：
```
找到多个匹配，你指的是哪一个？
1. 【群聊】产品讨论组（最近消息：...，未读：3）
2. 【私聊】产品经理-张三（最近消息：...）
3. 【公众号】产品周刊（最近推送：...）
请回复编号，或输入名称进一步确认。
```

候选信息包含：
- 编号
- 类型标签：【群聊】/【私聊】/【公众号】/【品牌服务】/【折叠】
- 名称
- 最近消息摘要（如有）
- 未读数（如有）

### 第三步：用户确认后执行
- 用户回复编号 → 直接使用该候选
- 用户回复名称 → 用该名称精确匹配后执行
- 用户说"都不是" → 建议用户用 `wx sessions` 或 `wx contacts` 查看完整列表，或提供更精确的名称

### 第四步：无匹配时
如果搜索结果为 0：
```
没有找到名称包含"XX"的会话/联系人。
可能的原因：
- 名称拼写不同（微信里的备注名/昵称可能和你说的不一样）
- 该联系人最近没有聊天记录（不在 sessions 列表里）
建议：
- 我可以列出所有会话/联系人，你看看是哪个
- 或者你提供更精确的名称/备注
```

## 特殊情况

### 1. 只有一个匹配
- 直接使用，不需要确认
- 但在回答中可以提一句"已为你查询 XX"

### 2. 用户明确指定类型
- 用户说"XX群" → 只在群聊中搜索，匹配到一个就直接用
- 用户说"XX这个人" → 只在私聊/联系人中搜索
- 类型明确时，即使有其他类型的同名结果，也不视为歧义

### 3. 群名显示为 chatroom ID
- 新创建的群可能显示为 `123456789@chatroom`
- 这不是歧义，直接用该 ID 查询即可
- 可以告知用户"这个群名还没同步到本地，显示为 ID，不影响查询"

### 4. 用户说"还是那个群""上次那个"
- 如果当前会话上下文里有明确提到过的群，直接使用
- 如果上下文不明确，触发歧义确认，列出最近活跃的几个群让用户选

## 验证场景

| 场景 | 预期行为 |
|------|---------|
| "帮我看看 coco 的聊天记录" | contacts 里有 coco 和 coco🐢，列出两个候选让用户选 |
| "产品群最近聊了什么" | sessions 里可能有多个含"产品"的群，列出候选 |
| "微信支付的消息" | 匹配到一个公众号/服务通知，直接使用 |
| "那个群" | 上下文不明确，列出最近活跃的群让用户选 |
| "不存在的人" | 无匹配，告知原因并建议查看完整列表 |

## 注意事项

- **禁止猜测**：即使 90% 确定是某个，只要有多个匹配，必须让用户确认
- **候选不超过 5 个**：如果匹配结果超过 5 个，列出最相关的 5 个，其余说"还有 N 个匹配，需要更精确的名称"
- **优先最近活跃**：候选按最后消息时间倒序排列，最近活跃的排前面
- **确认后记住**：用户确认过的名称映射，可以在当前会话中记住，后续不用重复确认（但换会话后需要重新确认）
