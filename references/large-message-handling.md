# 大消息量处理策略（wechat-control 参考）

> 当查询返回几百上千条消息时，避免一次性全部读取导致超时、token 超限或输出过大。采用"先概览、再深入、按需展开"的分层策略。

## 消息量分级

| 等级 | 消息数量 | 处理策略 |
|------|---------|---------|
| 小量 | ≤ 50 条 | 直接全部读取，完整摘要 |
| 中量 | 50-200 条 | 全部读取，精简摘要（核心话题 + 重要消息） |
| 大量 | 200-1000 条 | 分批次读取，先统计概览，再按话题聚类摘要 |
| 超大量 | > 1000 条 | 必须分批次，先统计 + 关键词搜索定位，不做全量读取 |

## 判断消息量的方法

1. **先查统计**：执行 `wx stats "<会话名>"`，获取总消息数、活跃时段、最活跃的人
2. **再查会话元信息**：`wx sessions` 里有最后消息时间，但没有总消息数
3. **试探性查询**：先用 `--limit 50` 查最近 50 条，根据输出判断是否还有更多
4. **按时间范围估算**：用户说"最近一年"，如果是活跃群，大概率超 1000 条，直接走大量策略

## 分层处理策略

### 第一层：统计概览（必做，适用于大量/超大量）

先给用户整体情况，不直接读具体消息：

```
【XX群 · 最近一年】消息量较大（约 N 条），先给你整体概览：

📊 整体情况：
- 总消息数：约 N 条
- 参与人数：M 人
- 最活跃的人：张三（N条）、李四（N条）
- 最活跃时段：晚上 20:00-22:00
- 消息类型：文本 X%、图片 Y%、链接 Z%

🔥 高频话题（基于关键词统计）：
1. 话题A（出现 N 次）
2. 话题B（出现 N 次）
3. 话题C（出现 N 次）

你想深入了解哪个方面？
- 回复话题编号，看该话题的详细讨论
- 回复"最近的消息"，看最近 50 条的摘要
- 回复"搜XX"，搜索特定关键词的消息
- 回复"按月看"，按月分批次查看
```

### 第二层：分批次读取（中量/大量）

按时间范围分批次，每次读取一个时间段：

**按月分批次**（适用于"最近一年"这种长周期）：
```
最近一年的消息按月分批：
1. 2026年9月（N条）
2. 2026年8月（N条）
3. 2026年7月（N条）
...
你想看哪个月？回复月份编号，我给你该月的详细摘要。
```

**按周分批次**（适用于"最近三个月"）：
```
最近三个月按周分批：
第1周（9.1-9.7）：N条
第2周（9.8-9.14）：N条
...
```

**每次读取限制**：
- 单批次不超过 200 条
- 用 `--since` 和 `--until` 限定时间范围
- 用 `--limit` 限制最大条数

### 第三层：高效摘要（读取后）

消息量大时，摘要要精简，突出重点：

**摘要结构**：
1. **核心话题**（3-5 个，每个一句话）
2. **重要消息**（@我/决策/紧急，不超过 5 条，每条一句话）
3. **活跃人物**（Top 3，每人一句话贡献）
4. **数据概览**（总条数、参与人数、时间范围）

**不做的事**：
- 不逐条列出所有消息
- 不复制大段原文（除非用户要求）
- 不展开每个话题的详细讨论（除非用户要求）

### 第四层：按需深入（用户要求后）

用户对某个话题/时间段感兴趣后，再深入：
- "展开话题1" → 读取该话题相关的消息，详细摘要
- "看9月的消息" → 读取 9 月的消息，按月摘要
- "搜预算" → 用 `wx search "预算" --in "群名"` 搜索特定关键词

## 技术实现要点

### 1. 限制单次查询输出
```bash
# 永远加 --limit，默认 50，最大不超过 200
wx history "群名" --limit 50

# 大消息量必须加时间范围
wx history "群名" --since 2026-09-01 --until 2026-09-30 --limit 200
```

### 2. 先用 stats 评估
```bash
# 先查统计，评估消息量
wx stats "群名"
# 根据 total 字段判断走哪个策略
```

### 3. 用 search 定位，不做全量扫描
```bash
# 用户关心特定话题时，直接搜索，不读全部消息
wx search "关键词" --in "群名" --since 2026-01-01 --limit 50
```

### 4. 分批次累加（需要全量时）
```bash
# 按月分批，每次读一个月
# 第1个月
wx history "群名" --since 2026-01-01 --until 2026-01-31 --limit 200
# 第2个月
wx history "群名" --since 2026-02-01 --until 2026-02-28 --limit 200
# ... 依次类推
# 每批摘要后，汇总成整体摘要
```

## 用户交互话术

### 检测到大消息量时
```
这个群最近一年的消息量比较大（约 N 条），全部读取可能会比较慢。

我建议这样：
1. 先给你整体概览（活跃度、高频话题、活跃人物）
2. 你按需深入某个话题或时间段

可以吗？或者你有特定想了解的方面（如某个话题、某段时间），我直接定位。
```

### 用户要求全部读取时
```
好的，全部读取会分批次进行，可能需要一点时间。

我会按月分批，每批给你一个摘要，最后给你整体汇总。
现在开始第1批（2026年9月）...
```

### 分批进行中
```
【第 N 批 / 共 M 批】2026年X月
- 消息数：N 条
- 核心话题：...
- 重要消息：...

继续下一批吗？还是先看看这批的详细内容？
```

## 注意事项

1. **永远不要不加限制地查全部历史**：`wx history "群名"` 不加 limit 可能返回几千条，导致超时
2. **默认 limit 50**：用户没说数量时，默认查最近 50 条
3. **先问后查**：大消息量时，先给用户概览和选择，不要闷头全量读
4. **统计优先**：能先用 stats 回答的问题（活跃度、活跃人物、消息类型分布），就不用读具体消息
5. **搜索优先**：用户关心特定话题时，直接用 search 定位，不读全部
6. **token 意识**：摘要时控制输出长度，大消息量的摘要不超过 500 字，详细展开不超过 2000 字
