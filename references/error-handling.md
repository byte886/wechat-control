# 错误处理与友好提示（wechat-control 参考）

> wx-cli 命令失败时，禁止直接把原始报错丢给用户。按以下映射表翻译成友好提示 + 原因分析 + 解决建议。

## 错误映射表

### E1: 微信未运行

**原始报错特征**：
- `wx init` 时提示找不到 WeChat/Weixin 进程
- `task_for_pid` 失败，PID 不存在
- 查询时报数据库文件被占用或无法访问

**友好提示**：
```
微信没有在运行。wx-cli 需要从微信进程内存中读取数据库密钥，微信必须处于登录并运行状态。

解决方法：
1. 打开微信并登录你的账号
2. 保持微信在后台运行（不用停留在某个界面）
3. 然后重新查询即可
```

### E2: 密钥未提取 / 密钥失效

**原始报错特征**：
- `无法解密 session.db`
- `无法解密 message.db`
- `all_keys.json` 为空或不存在
- `wx init` 时 `成功提取 0 个数据库密钥`

**友好提示**：
```
数据库密钥没有提取成功，无法解密微信数据。

可能的原因：
1. 还没有执行过 `wx init` 提取密钥
2. 微信版本过高（4.1.10+），密钥存储格式变了，wx-cli 扫描不到
3. 提取密钥时登录的账号和当前登录的账号不是同一个（数据目录不匹配）
4. macOS 上 SIP 没有关闭，或没有用 sudo 执行

解决方法：
1. 确认微信版本是 ~4.1.8（微信设置→关于微信查看）
2. 确认当前登录的是要查询的账号
3. macOS：确认 SIP 已关闭（csrutil status），然后执行 `sudo wx init --force` 重新提取
4. Windows：以管理员身份运行 PowerShell，执行 `wx init --force`
5. 看到"成功提取 N 个数据库密钥"后再查询
```

### E3: 权限不足（macOS SIP / Windows 管理员）

**原始报错特征**：
- macOS: `task_for_pid 失败 (kr=5)`
- macOS: `Operation not permitted`
- Windows: `拒绝访问` / `Access is denied`
- Windows: 需要提升权限

**友好提示**：
```
权限不足，无法读取微信进程内存。

macOS 解决方法：
1. 确认 SIP 已关闭：终端执行 `csrutil status`，应显示 `disabled`
2. 如果 SIP 是 enabled，需要重启到恢复模式关闭 SIP（黑苹果：修改 OpenCore config.plist 添加 csr-active-config=EF0F0000）
3. 用 sudo 执行：`sudo wx init`

Windows 解决方法：
1. 右键 PowerShell → 以管理员身份运行
2. 在管理员 PowerShell 中执行 `wx init`
```

### E4: 群名/人名不存在 / 无匹配

**原始报错特征**：
- `wx history "不存在的名"` 返回空或报错
- 搜索结果 count: 0

**友好提示**：
```
没有找到名称为"XX"的会话或联系人。

可能的原因：
1. 名称拼写不同（微信里的备注名/昵称可能和你说的不一样）
2. 该联系人/群最近没有聊天记录（不在最近会话列表里）
3. 这是公众号或服务通知，名称和你说的不完全一致

建议：
- 我可以列出所有最近会话，你看看是哪个（回复"列出所有会话"）
- 或者列出所有联系人，你找找（回复"列出所有联系人"）
- 或者你提供更精确的名称/备注
```

### E5: 搜索无结果

**原始报错特征**：
- `wx search "关键词"` 返回 `count: 0`
- `results: []`

**友好提示**：
```
没有搜索到包含"XX"的消息。

可能的原因：
1. 关键词只出现在合并聊天记录或公众号标题中，不被全文索引
2. 时间范围太窄，可以扩大范围试试（如"最近一年"）
3. 消息类型不匹配，可以去掉类型过滤
4. 关键词太具体，可以换更短/更常见的词试试

建议：
- 换个更短的关键词试试
- 或者扩大时间范围（如"帮我搜一下最近一年关于XX的消息"）
- 或者我直接列出这个群最近的消息，你看看有没有相关内容
```

### E6: wx-cli 未安装 / 命令不存在

**原始报错特征**：
- `wx: command not found`
- `wx: 未找到命令`
- `/usr/local/bin/wx: No such file or directory`

**友好提示**：
```
wx-cli 还没有安装。

安装方法（macOS）：
1. 安装 Node.js：`brew install node`
2. 安装 wx-cli：`npm install -g @jackwener/wx-cli`
3. 如果 postinstall 被阻止：`npm install -g --allow-scripts=@jackwener/wx-cli @jackwener/wx-cli`
4. 验证：`wx --version`

安装方法（Windows）：
1. 安装 Node.js（nodejs.org 或 winget install OpenJS.NodeJS）
2. 管理员 PowerShell 执行：`npm install -g @jackwener/wx-cli`
3. 验证：`wx --version`
```

### E7: 数据目录配置错误

**原始报错特征**：
- `找不到数据目录`
- `db_dir` 指向不存在的路径
- 配置的账号目录和当前登录账号不匹配

**友好提示**：
```
微信数据目录配置有问题。

可能的原因：
1. 之前提取密钥时登录的是 A 账号，现在登录的是 B 账号，配置里的 db_dir 还指向 A 账号
2. 微信数据目录被移动或删除
3. 手动修改了 config.json 里的路径

解决方法：
1. 确认当前微信登录的是要查询的账号
2. 重新执行 `wx init --force`，会自动检测当前登录账号的数据目录并更新配置
3. macOS 数据目录通常在：~/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/<wxid>/db_storage/
4. Windows 数据目录在：文档\WeChat Files\<wxid>\（微信设置→文件管理中查看）
```

### E8: 输出过大 / 消息量太多

**原始报错特征**：
- 命令执行时间过长
- 输出被截断
- 终端卡顿
- token 超限

**友好提示**：
```
这个会话的消息量比较大，全部读取可能会比较慢。

建议：
1. 缩小时间范围（如"最近一周"而不是"全部消息"）
2. 限制消息数量（默认查最近 20 条，可以说"最近 50 条"）
3. 先看统计信息了解整体情况（"这个群的活跃度怎么样"），再决定要不要深入看具体消息
4. 用关键词搜索定位感兴趣的内容（"帮我搜一下这个群里关于XX的消息"）

你想怎么查？我可以按你指定的范围来。
```

### E9: wx-daemon 启动失败

**原始报错特征**：
- `启动 wx-daemon... 失败`
- `daemon.sock` 权限错误
- 端口被占用

**友好提示**：
```
wx-cli 后台守护进程启动失败。

解决方法：
1. 先停止可能残留的 daemon：`wx daemon stop`
2. 清理临时文件：macOS 执行 `rm -rf ~/.wx-cli/daemon.sock ~/.wx-cli/cache/`
3. 重新执行查询命令，daemon 会自动重启
4. 如果还是失败，重启微信后再试
```

### E10: 微信版本过高

**原始报错特征**：
- `wx init` 时 `找到 0 个候选密钥`
- 微信版本是 4.1.10 或更高

**友好提示**：
```
你的微信版本过高，wx-cli 可能无法提取密钥。

当前情况：
- wx-cli 支持微信 ~4.1.8
- 微信 4.1.10+ 改变了密钥在内存中的存储格式，传统内存扫描方式提取不到
- 你的微信版本是：XX（需要确认）

解决方法（二选一）：
1. 降级微信到 4.1.8（推荐）：
   - 从腾讯官方下载 4.1.8 安装包
   - 备份当前微信数据
   - 卸载当前版本，安装 4.1.8
   - 登录后关闭自动更新
2. 等待 wx-cli 新版本支持更高微信版本（不确定时间）
```

### E11: wx init 提示需要重签微信，要重签吗？

**不要重签。** 那是 wx-cli 的默认文案，假设用户用重签方式提取。关 SIP + sudo（macOS）/ 管理员 PowerShell（Windows）即可不重签提取。重签会改变微信 code identity，历史上曾触发强制下线 + 违规提示，是风控红线（见 SKILL §2 密钥提取红线）。

### E12: 群名/会话显示为一串 ID（如 xxxxxxxxxx@chatroom）？

这是正常现象：群名称尚未同步到本地数据库。用该 ID 同样可以查询历史、成员、统计。在微信里打开该群聊一次，群名称可能会同步。

### E13: 可以用大号（主号）吗？

只读查询可以，但建议先在小号跑通所有功能。大号读取同样安全（纯本地文件操作），但大号更重要，建议等功能稳定、错误处理完善后再用于只读。**写操作（发消息/自动回复）严禁在大号执行**，仅限小号（见 SKILL §2 账号表与 §6）。切换大号后需重新 `sudo wx init` 提取大号密钥。

### E14: 读取微信数据会被微信官方发现吗？

不会。wx-cli 读取的是微信本地数据库文件（SQLite + SQLCipher），不碰微信进程、不联网、不操作微信界面，微信完全感知不到。密钥提取时短暂附加进程，但"关 SIP + sudo + 不重签"方式是安全的，且只在提取密钥时发生一次。

### E15: Windows 上能用吗？

wx-cli 官方支持 Windows（win32-x64 预编译二进制 + PowerShell 安装脚本），加密原理和密钥格式三平台通用。但**本技能 Windows 部分尚未实测**，基于官方文档和原理编写。要点：
- 以**管理员身份**运行 PowerShell（读取 Weixin.exe 进程内存需要）
- 不需要关 SIP（Windows 无此机制）
- 微信版本同样需 ~4.1.8（4.1.10+ 提取可能失败）
- 数据目录在"文档\WeChat Files\<wxid>\"（微信设置→文件管理中查看）
- 首次使用建议先在微信小号上验证密钥提取和数据读取，确认无误后再用于正式环境

## 处理原则

1. **先判断错误类型**：根据原始报错特征匹配到 E1-E10 中的某一类
2. **给友好提示**：用用户能理解的语言说明发生了什么
3. **分析原因**：列出可能的原因（2-4 条）
4. **给解决建议**：提供可操作的解决步骤，按优先级排列
5. **不丢原始报错**：如果用户需要排查，可以在最后附上原始报错的关键信息（但不要一上来就丢）
6. **能自动修复的自动修复**：比如 daemon 失败可以自动执行 stop + 清理，不需要用户手动操作

## 未知错误

如果报错不匹配以上任何一类：
```
遇到了一个未预期的错误：<简要描述>

我正在分析原因。为了帮你解决，请提供：
1. 你执行的具体操作（如"查XX群的历史消息"）
2. 完整的错误信息（如果有的话）

同时你可以先试试：
1. 确认微信在运行且登录了正确的账号
2. 重新执行 `sudo wx init --force`（macOS）或管理员 PowerShell `wx init --force`（Windows）
3. 重启微信后再试
```
